# Auditoría de la feature de comentarios

Alcance: la feature de comentarios del blog «Corriente» (POST, PATCH y DELETE de comentarios, tabla `comentarios` y su semilla, `comentarios.spec.ts`, `Comentarios.jsx` y lo que el detalle, el listado y los relacionados hacen con los comentarios), a fecha 2026-10-20. Verificación: leí `CLAUDE.md`, el README, `routes.ts` entero, las migraciones, la semilla, el test y la arquitectura de referencia (auth); ejecuté `npm test` (1 test, verde), hice GET a la API real (3401) y probé escrituras, una prueba de mutación y la cobertura c8 en una copia desechable del backend (puerto 3412, base propia), sin tocar la base real. Prioridad: primero lo que expone datos, rompe una regla de negocio o afecta a usuarios reales; un hallazgo que desbloquea a otros va antes que los que desbloquea; después validación, tests y arquitectura. «Sí» en la casilla 5 significa que el arreglo es solo código y un `git revert` devuelve el estado anterior; «No», que deja datos, esquema o información filtrada que el revert no deshace.
